## 2단계: 설명 품질

- 요약 프롬프트 v4: 문서 검토 지침 10개(계획·설계 단계 표현, 3문장 구조와 문장 길이, 용어 풀어 쓰기, 코드명 처리, 한 줄 설명 형식, "~하기" 기능, 용어 통일, 날짜·이슈 번호 표기, git 아님 표기, 실험·설계 폴더 섹션 이름) 반영
- 인사이트 프롬프트 v2: 근거 프로젝트·숫자, 개수와 나열 일치, 수익은 가정→계산→결과, 추상 결론엔 측정 방법, 법적 확인 남으면 "바로 공개 가능" 금지
- 화면 용어 통일: "실행 중"(LIVE 대체), "git 아님", AI 이름은 "Claude"(모델명은 툴팁), 갱신 시각 라벨 구분("설명 갱신", "인사이트 분석")
- 반영 후 전체 재생성(Shift+새로고침 1회, Opus 1회)

## 3단계: 구조 개편

- 상세: 이름 행 → 큰 한 줄 설명 → 메타 줄(활동 상태 · 마지막 개발 YYYY-MM-DD(n일 전) · 실행 칩) → 이 프로젝트는 → 현재 상태·다음 할 일 → AI 제안(있을 때) → "개발 정보" 구역(실행 박스, 이슈·커밋, 기술 구성). 빈 구역은 한 줄로 접기
- 첫 화면: "지금 실행 중" 줄 → "현황 · git·GitHub 집계" 구역(지표 카드 클릭 시 필터 적용) → "AI 제안 · Claude" 구역(배경 구분, 서비스 후보 → 정리 제안 → 아이디어 → 개발 성향(접힘))
- 목록: 실행 중 행에 포트 칩, 실행 표시를 활동 점과 다른 모양·색으로, "오래된 순" 정렬, 시간에 날짜 툴팁
- 필터를 바꿔도 보던 프로젝트 유지
- 26주 막대에 월 라벨, 잊혀진 작업 "더 보기"(미커밋 필터로 이동)
