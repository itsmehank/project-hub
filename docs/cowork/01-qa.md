# Cowork 프롬프트 1 — 기능 QA

아래 내용을 Cowork에 그대로 붙여 넣는다.

---

너는 꼼꼼한 QA 엔지니어다. 내 맥에서 로컬로 돌아가는 웹 대시보드 **Project Hub**를 실제로 사용해 보면서 버그, 오작동, 깨진 화면, 데이터 오류를 찾아 보고서로 정리해 줘. 코드나 파일은 수정하지 말고, 사용자처럼 화면을 조작해서 확인한다.

## 서비스 설명

- `~/git/personal` 아래 개인 프로젝트 31개를 한 화면에서 보여주는 대시보드다.
- 주소: http://127.0.0.1:5199 (API 서버는 http://127.0.0.1:4310)
  - 접속이 안 되면 터미널에서 `cd ~/git/personal/project-hub && pnpm dev`를 실행한 뒤 다시 시도한다.
- 화면 구성 (주소 해시로 이동한다)
  - `#/` 첫 화면: 포트폴리오 인사이트
    - 지표 카드, 26주 커밋 추이, 스택 분포, 주목할 프로젝트
    - Opus 분석: 개발 성향, 서비스 후보, 신규 아이디어, 정리 제안
  - `#/p/<프로젝트명>` 프로젝트 상세
    - 실행 상태, 이 프로젝트는, 현재 상태, GitHub 이슈·커밋, 기술 구성
  - `#/p/<프로젝트명>/issues`(뒤에 `/closed`, `/pr` 가능) 이슈·PR 전체 페이지
- 왼쪽 목록 기능
  - 필터 칩: 전체, 실행 중, 활성, 휴면, 방치, 미커밋
  - 정렬, ⌘K 검색, ↑↓ 키로 프로젝트 이동
- 오른쪽 위 새로고침: 폴더 재스캔 → git fetch·상태 수집 → GitHub 이슈·PR·CI 갱신 → 바뀐 프로젝트만 Claude 요약 재작성 → 인사이트 재분석
- 실행 관리
  - 프로젝트 폴더에서 돌고 있는 프로세스를 "실행 중"(LIVE)으로 표시하고, 포트가 있으면 `localhost:포트` 링크를 보여준다.
  - 실행 명령이 있으면 ▶ 실행 버튼이 나온다. Claude가 추정한 명령은 처음 실행할 때 승인 모달을 거친다.
  - 허브가 띄운 프로세스는 바로 중지된다. 터미널에서 직접 띄운 프로세스("직접 실행")는 확인 모달을 거친다.
  - 로그 보기와 명령 편집 기능이 있다.

## 반드시 지킬 것 (실제 내 작업 환경이다)

1. **직접 실행 중인 프로세스는 절대 중지하지 마라.** 지금 kr-by-claude, movie-sniper, route-guide, mx5-bot이 내가 띄운 상태다. 이 프로젝트들의 "중지" 버튼은 확인 모달이 뜨는 데까지만 보고 **취소**한다.
2. 실행·중지 테스트는 **hw-note**(astro 개발 서버, 포트 4321)와 **sam-kingdom-textgame**(vite)으로만 한다. 띄운 것은 테스트가 끝나면 반드시 허브에서 중지한다.
3. 비용이 드는 작업은 정해진 횟수만 한다.
   - "인사이트 다시 분석"(Opus 호출, 1~2분): 최대 1회
   - 일반 새로고침: 최대 2회
   - **Shift+새로고침(전체 31개 요약 재생성, 약 3분)은 하지 않는다.**
4. "명령 편집"으로 명령을 바꿨다면 테스트 후 원래 값으로 되돌린다.
5. "VS Code로 열기"는 한 프로젝트에서 한 번만 눌러 본다.
6. `~/git/personal` 아래 파일을 만들거나 지우지 않는다. 폴더 추가·삭제 반영 테스트가 꼭 필요하면 `~/git/personal/zz-qa-test` 빈 폴더 하나만 만들었다가 확인 후 지운다.

## 점검 항목

각 항목을 직접 해 보고 "기대 동작"과 실제가 다르면 기록한다.

**A. 첫 화면 (`#/`)**
- 지표 카드 숫자가 왼쪽 목록의 필터 칩 숫자(실행 중, 활성, 휴면, 방치)와 일치하는가
- 26주 커밋 막대와 스택 분포가 그려지는가. 막대에 마우스를 올리면 주차와 개수가 나오는가
- "요즘 가장 활발한", "이슈가 쌓인", "잊혀진 작업" 항목을 누르면 해당 프로젝트 상세로 가는가
- Opus 분석 섹션의 프로젝트 칩과 "프로젝트 보기"가 모두 실제 프로젝트로 연결되는가(깨진 링크가 없는가)
- "인사이트 다시 분석" 1회: 분석 중 표시 → 완료 후 내용과 "Opus 분석 n분 전"이 갱신되는가
- 제목 "Project Hub"를 누르면 어느 화면에서든 첫 화면으로 오는가

**B. 목록과 탐색**
- 필터 칩 6개: 툴팁 문구가 나오는가, 화면 밖으로 잘리지 않는가, 필터 결과가 문구 정의와 맞는가
  - 예: 활성 = 14일 이내 커밋. 몇 개 프로젝트의 "n일 전" 표시로 검증한다.
- 정렬 3종(최근 활동순, 이름순, 이슈 많은 순)이 맞게 정렬되는가
- ⌘K로 검색창 포커스, 검색어 입력, Esc로 지우기
- 상세 화면에서 검색해 보던 프로젝트가 결과에서 빠지면 첫 결과로 이동하는가
- 상세 화면에서 ↑↓로 프로젝트가 이동하는가. 첫 화면과 이슈 페이지에서는 ↑↓가 스크롤로만 동작하는가
- 브라우저 뒤로 가기·앞으로 가기, 상세 주소 직접 입력(예: `#/p/mx5-bot`), 존재하지 않는 프로젝트 주소(`#/p/없는이름`)

**C. 프로젝트 상세**
- 최소 6개 프로젝트를 고루 확인한다.
  - 실행 중: kr-by-claude, mx5-bot
  - git이 아님: btc-price-period-analysis, navi-lane-probe
  - 커밋 없음: sonjas
  - GitHub 없음: name-collector
  - 각 섹션이 깨지지 않고, 빈 상태 문구가 자연스러운가
- 태그(활동 상태, 스택, 브랜치 ↑↓, 미커밋, CI)가 실제 상태와 맞는가
  - 의심되면 터미널 `git -C ~/git/personal/<이름> status -sb`로 대조한다(읽기만).
- 실행 상태 박스
  - 포트 링크를 누르면 실제 서비스가 열리는가
  - 직접 실행 프로세스의 중지 → 확인 모달 → **취소**
- hw-note 실행 시나리오
  - 승인 모달(처음이면) → 실행 → LIVE와 localhost:4321 링크
  - 로그 보기가 실시간으로 갱신되는가
  - 중지가 확인 없이 바로 되는가
- 명령 편집
  - 잘못된 포트(예: `abc`, `70000`)는 저장이 막히는가
  - 저장 후 표시가 갱신되는가, 원복은 되는가
- sam-kingdom-textgame 실행 시 포트 5173이 kr-by-claude와 충돌한다는 경고가 나오는가
  - 경고가 안 나오고 실행되면, 다른 포트로 떴는지 확인하고 중지한다.

**D. 이슈 전체 페이지**
- kr-by-claude 기준으로 확인한다.
  - 열린 이슈 수가 GitHub 화면과 같은가(현재 33개 전후)
  - 닫힌 이슈 탭, PR 탭이 동작하는가
- 검색(제목, 본문, `#번호`), 라벨 필터(여러 개 동시 선택), 정렬 4종
- 본문 펼치기와 GitHub 링크
- 상세의 "이슈 전체 보기 (N)", "더 보기"(열린 이슈, PR, 닫힌 이슈 각각)가 올바른 탭으로 여는가
- GitHub가 없는 프로젝트의 이슈 주소(`#/p/name-collector/issues`)에서 안내가 나오는가

**E. 새로고침**
- 툴팁 문구
- 진행 링과 `n/total` 표시
- 새로고침 중 버튼을 다시 눌러도 오류가 없는가
- 완료 후 "n분 전 갱신" 표시가 갱신되는가

**F. 공통**
- 콘솔 오류: 개발자 도구 Console에 빨간 오류가 있는가
- 레이아웃: 창 너비를 1280px, 1024px로 줄였을 때 깨지거나 겹치는 곳이 있는가
- 한글 깨짐, 잘린 문구, 겹치는 툴팁, 애니메이션 끊김

## 이미 알고 있는 문제 (다시 보고하지 않아도 됨)

- mx5-bot은 봇이 실행 중인데도 ▶ 실행 버튼이 함께 보인다. 추정 명령 `./run_bot.sh`와 실제 프로세스 명령이 달라서다.
- 열린 이슈가 50개를 넘는 저장소는 탭 숫자가 50에서 멈춘다(현재 해당 없음).
- 백그라운드 탭에서는 애니메이션과 데이터 갱신이 늦게 반영될 수 있다.

## 결과물 형식

1. **요약**: 전체 판정(배포 가능 / 수정 후 가능 / 불가), 발견 건수(심각도별)
2. **발견 목록** 표: `번호 | 심각도(치명/높음/보통/낮음) | 화면 | 재현 단계 | 기대 동작 | 실제 동작 | 스크린샷`
   - 심각도 기준
     - 치명: 데이터 손실이나 의도치 않은 프로세스 중지
     - 높음: 핵심 기능 불가
     - 보통: 우회 가능한 오류
     - 낮음: 표시·문구
3. **통과한 항목** 체크리스트(A~F)
4. **정리 확인**: 테스트로 띄운 프로세스를 모두 중지했는지, 편집한 명령을 원복했는지, 만든 폴더를 지웠는지
